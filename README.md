# acme-health

Generated by [workshop-demo-generator](../../) — a Twilio workshop demo scaffolded
for **typescript · SDK**. An inbound AI voice agent for a (fictional) clinic, built on
**Twilio Agent Connect (TAC)**, with a **LangChain** agent running Claude by default.

## Setup

Needs **Node 22.13+** (TAC's minimum) — `nvm use` picks it up from `.nvmrc`.

```bash
cp .env.example .env       # fill in Twilio + model provider creds and PUBLIC_HOST
./run.sh                   # install deps + start backend on :8080 and the wallboard
```

Then hit the health check:

```bash
curl http://localhost:8080/health
# {"status":"ok"}
```

Point your Twilio number's **Voice webhook** at `https://<PUBLIC_HOST>/twiml` (POST).

## TAC modes — switch with one env var

| Mode | Set | You get |
| --- | --- | --- |
| ConversationRelay-only | `TWILIO_CONVERSATION_CONFIGURATION_ID` empty | Voice agent, sample knowledge base, PSTN warm transfer |
| Orchestrated | `TWILIO_CONVERSATION_CONFIGURATION_ID=conv_configuration_…` | + Conversation Orchestrator, Conversation Memory in the prompt, optional Enterprise Knowledge (`TWILIO_KNOWLEDGE_BASE_ID`) and Studio handoff (`TWILIO_STUDIO_HANDOFF_FLOW_SID`) |

The code is the same in both modes; restart after changing `.env`. In orchestrated
mode the app fetches the configuration at startup and exits if it can't.


## Swapping the model

Set `LLM_MODEL=provider:model` and the matching API key, then restart:

| `LLM_MODEL` | Package | Key |
| --- | --- | --- |
| `anthropic:claude-opus-5-5` (default) | `@langchain/anthropic` (installed) | `ANTHROPIC_API_KEY` |
| `openai:gpt-5.4-mini` | `@langchain/openai` (installed) | `OPENAI_API_KEY` |
| `google-genai:…`, `ollama:…`, `bedrock:…`, … | `npm install @langchain/<provider>` | that provider's key |

Tools, prompts and handlers don't change. Claude keeps its tuned settings (effort,
refusal fallbacks, prompt caching); other providers run with their defaults. Pick a
model that supports tool calling and streaming.

## Routes

| Route | Served by | Purpose |
| --- | --- | --- |
| `POST /twiml` | TAC | Inbound call → ConversationRelay TwiML |
| `WS /ws` | TAC | ConversationRelay WebSocket |
| `POST /transfer/*` | `src/tools/warmTransfer.ts` | Warm transfer to the office |
| `POST /webhook` | TAC | Conversation Orchestrator events (orchestrated mode) |
| `POST /transcripts/webhook` | `src/transcripts/routes.ts` | Orchestrator status callbacks → transcripts |
| `GET /calls`, `GET /calls/stream` | `src/transcripts/routes.ts` | Wallboard transcripts (snapshot / SSE), local only |
| `GET /events` | `src/observability.ts` | Wallboard feed |

Every Twilio-facing route checks the `X-Twilio-Signature`, so `PUBLIC_HOST` must match
the host Twilio calls exactly.

## Live transcripts on the wallboard

The wallboard shows each call live, labelled **Customer / AI agent / Office**. After a
warm transfer, the office person's words appear in the same call, below a "Transferred
to office" divider.

- **Source:** Conversation Orchestrator status callbacks (`COMMUNICATION_CREATED`,
  `PARTICIPANT_*`, `CONVERSATION_*`) posted to `POST /transcripts/webhook`. No polling.
- **Transcription:** ConversationRelay ingests the AI portion (TAC puts
  `conversationConfiguration` on its TwiML, which creates the conversation TAC then
  looks up by Call SID). At a warm transfer, `/transfer/action` starts
  `<Transcription conversationId>` on the caller's leg for the human portion. One
  speech-to-text engine at a time. Keep **VOICE capture rules off** for this number:
  with them on, calls run two engines (and on this account passive capture fails with
  error 32650, so TAC can't find a conversation and the call never starts).
- **Lifecycle:** VOICE timeouts are `inactive: 5, closed: 15` minutes so the
  conversation is still open when the human portion starts.
- **Push:** the wallboard reads `GET /calls/stream` (Server-Sent Events).
- **Storage:** transcripts are cached in the app's SQLite file (`EVENTS_DB_PATH`) so
  restarts keep them; Orchestrator remains the record. Calls older than
  `TRANSCRIPT_RETENTION_DAYS` (default 7) are deleted at startup. `/calls` and
  `/calls/stream` answer local requests only.

One-time setup (and again whenever `PUBLIC_HOST` changes):

```bash
npm run add-status-callback            # shows the statusCallbacks change
npm run add-status-callback -- --apply # sends it (keeps existing callbacks)
```

`npm run create-voice-config` creates the dedicated `acme-health-voice` configuration
(no capture rules, the timeouts above) if you need to rebuild it.

## Clinic FAQ for Enterprise Knowledge

`docs/knowledge/acme-health-faq.md` is a sample FAQ (31 questions, fictional clinic) written
for retrieval: one question per heading, and every answer makes sense on its own.

```bash
npm run upload-knowledge            # preview: shows the knowledge base and its sources
npm run upload-knowledge -- --apply # uploads the FAQ to TWILIO_KNOWLEDGE_BASE_ID, then test-searches it
```

`knowledge_lookup` searches it when `TWILIO_KNOWLEDGE_BASE_ID` is set in orchestrated mode.

## Sample data

Patients for caller verification are in `src/data/patients.ts` — e.g. say you're
**Jamie Sample, born April 12 1985**. All of it is invented.

## Events (§6)

Table layout for events and transcripts: [`docs/schema.md`](docs/schema.md).

Every integration records what it does to an events store, exposed at
`GET /events`. The store backend is set by `EVENTS_BACKEND` (default `sqlite`,
written to `EVENTS_DB_PATH`, default `events.db`) and is swappable without
regenerating.

```bash
curl 'http://localhost:8080/events?limit=50'
```

## HIPAA note

This is a demo with fake data. Before real patients call it: the Twilio account needs
a BAA and HIPAA-eligible configuration, caller speech goes to the model provider (needs
its own BAA / zero-retention arrangement), and voicemail recordings from `/transfer/recover-choice`
contain PHI. Set `TAC_ANALYTICS_DISABLED=true` if your policy requires it.

## Demo script

1. **Confirm the app boots** — `./run.sh` and `curl :8080/health`.
2. **Show the layering** — `src/tac/` (TAC wiring), then `src/handlers/` (the agent's
   callbacks), `src/prompts/` and `src/tools/`.
3. **Call the number** — ask about parking, then book an appointment as Jamie Sample.
4. **Ask for a person** — watch the warm transfer dial the office.
5. **Open the wallboard** at http://localhost:5175 and click **Refresh** to watch
   events stream in.
6. **Flip to orchestrated mode** — set `TWILIO_CONVERSATION_CONFIGURATION_ID`, restart,
   call again, and show memory from the first call carried into the second.
